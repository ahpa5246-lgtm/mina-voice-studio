# خطة 90 يومًا لانتشار Mina Voice Studio — جدول قابل للتنفيذ

هذه خطة هدفها بناء مستخدمين ومساهمين حقيقيين، **ليست وعدًا بمئة أو ألف نجمة**. تواريخ البدء مرنة. لا تحتاج ميزانية مدفوعة، لكن توليد نماذج GPU قد يخضع لحصص Kaggle والتراخيص وتكاليف أجهزة المستخدمين.

## أسبوع التأسيس — الأيام 1–7
| اليوم | المهمة | دليل الإنجاز |
|---|---|---|
| 1 | ضبط About description وTopics وصورة المشاركة وتوثيق المؤسسة | ظهور الإعدادات لزائر عام |
| 2 | CODEOWNERS وقواعد main وفتح Discussions | اختبار PR يتطلب مراجعة وفق ما تدعمه الخطة |
| 3 | مراجعة README/فيديو 60–90 ثانية بواجهة حقيقية | مستخدم يتبع 3 خطوات تثبيت |
| 4 | اختيار أول 5 Issues من بنك المهام + labels | رابط مباشر لكل مهمة ومعيار قبول |
| 5 | نشر مقال تقني واحد على DEV Community | رابط المقال، سؤال حقيقي في نهايته |
| 6 | تسجيل مشكلة تثبيت من مستخدم آخر وإصلاحها | Issue → PR → اختبار أخضر |
| 7 | مراجعة ما نجح وتعديل أولويات الأسبوع القادم | تقرير أسبوعي من 10 أسطر |

## الأسبوع 2 — أول تجربة خارج الفريق
- احصلي على متطوع واحد لديه جهاز Windows مختلف، وآخر Linux إن أمكن.
- كلفيهما بمهام صغيرة قابلة للتكرار، **دون أن تطلبي منهما Stars مقابل العمل**.
- أنتجي فيديو "make a dialogue with two characters" وارفقي المصدر الصوتي المرخص.
- شاركي شرحًا واحدًا في مجتمع ذي صلة يسمح به، لا تنشري في عشرة مجتمعات دفعة واحدة.
- اجمعي ثلاثة أسئلة متكررة وحدثي FAQ.

## الأسبوع 3 — جودة الصوت والشفافية
- أعيدي فحص Qwen على نموذج وبيانات ثابتة أو أوضحي حدود تجربة Kaggle الحالية.
- وثقي Chatterbox/Applio على عتاد متاح **إذا** كانت البيانات مرخصة والـGPU متوفر.
- لا تقولي إن "AI works everywhere"؛ فرقي بين تشغيل الواجهة، تحميل النموذج، جودة الصوت.
- حوّلي نتائج الفشل إلى مهام للباحثين أو مطوري الصوت وأشكري من ساعد.

## الأسبوع 4 — أول إصدار مجتمعي
- ادمجي على الأقل PR صالحًا من مساهم خارجي إن توافر؛ لا تقبلي PR شكليًا لتحقيق الرقم.
- انشري Release notes: قبل/بعد، الاختبارات، المتطلبات، المساهمون، مشاكل غير محلولة.
- اجمعي فيديو 60 ثانية ومقال "what we learned in 30 days" دون مبالغة.
- راجعي تجهيز Show HN/Product Hunt؛ إذا لا يوجد منتج سهل التجربة، أجّلي الإطلاق.

## الأيام 31–60 — بناء المجتمع المنتظم
**كل أسبوع:** 1 تحديث توثيق، 1 Issue مخصصة للمبتدئ، 1 عرض تجريبي، 1 تقرير حالة مختصر و1 مراجعة PRs.
- الأسبوع 5: تحسين المثبت وHardware preflight، مسار Windows.
- الأسبوع 6: مراجعة UX وRTL والوصولية مع مساهمين.
- الأسبوع 7: تجربة A/B حوار ومكتبة أمثلة مرخصة.
- الأسبوع 8: نشر نتائج benchmark شفافة مع تلخيص إسهامات المجتمع.
**قنوات التواصل:** DEV للمقالات، GitHub Discussions للدعم، YouTube للفيديو، Reddit عند وجود مشاركة مفيدة تتوافق مع القواعد.

## الأيام 61–90 — توسع مدروس
- الأسبوع 9: استضافة مراجعة تقنية عامة غير مدفوعة (GitHub Discussions) حول المشاكل المفتوحة.
- الأسبوع 10: توثيق Workflow للعبة مستقلة/رسوم متحركة مع مطور متعاون وذكر رخصة محتواه.
- الأسبوع 11: نسخة أكثر نضجًا لمثبت أو محرر صوت أولي، لا تضعي ألقاب Stable قبل إثباتها.
- الأسبوع 12: مراجعة readiness لنشر Show HN أو Product Hunt إن كان التشغيل سهلًا، والاستعداد للرد على المجتمع.
- الأيام 85–90: تحليل عميق للمقاييس؛ توقفي عن القنوات التي لا تجذب مستخدمين حقيقيين وركزي على أكثرها فائدة.

## ماذا لو فشل إعلان أو لم تأتِ نجوم؟
راجعي: هل جمهوره مناسب؟ هل العنوان يعد بأكثر مما يعمل؟ هل يستطيع الزائر تجربة شيء دون تثبيت أوزان ضخمة؟ هل لديك صفحة Features وTroubleshooting؟ هل يوجد سؤال أو مساهمة واضحة؟ أصلحي التحويل بدلاً من تكرار المنشور وتوسيع السبام.

## أهداف اختيارية لا وعود
يمكن اختيار أهداف داخلية مثل: 20 تجربة فعلية، 5 مشاكل مثبتة، 3 PRs خارجية ذات قيمة، 100 نجمة **كهدف غير مضمون**. سجلي خط الأساس الحقيقي أولًا (عند الإعداد: صفر نجوم). كل أسبوع قارني نتائج واقعية، ولا تخترعي أرقامًا للتسويق.
