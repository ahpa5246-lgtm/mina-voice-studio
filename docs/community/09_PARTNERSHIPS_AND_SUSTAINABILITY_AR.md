# الشراكات والانتشار المستدام لمشروع Mina Voice Studio

## أشكال التعاون التي نبحث عنها
1. **مطورو أنيميشن مستقلون**: يصنعون مشهدًا قصيرًا بأصوات مرخصة ثم يقدمون مشكلة واحدة محددة في المنتج.
2. **مطورو ألعاب مستقلة**: يختبرون أصوات NPC، ملفات WAV وتعدد المتحدثين؛ نضيف Workflow إلى الدليل مع توثيق صوت/ترخيص.
3. **باحثو Speech/ML**: يقدمون قياسات قابلة للتكرار لجودة العربية والإنجليزية وحالات الفشل ومخاطر التعميم.
4. **مطورو Python/FastAPI**: يحسنون API والتثبيت وعزل البيئة ومراجعة الاختبارات.
5. **مختصو الصوت والمؤثرات**: يراجعون RVC والضوضاء، الحروف المبتورة، Resampling وA/B.
6. **مترجمون ومختصو وصولية**: يدققون العربية والإنجليزية والـRTL ومفاتيح الوصول.
7. **أساتذة وطلاب هندسة**: يقدمون دروسًا/أمثلة قابلة لإعادة الإنتاج ويفتحون PRs بدلاً من نسخ أفكار جاهزة بلا توثيق.

## كيف نبدأ شراكة دون فقد هوية المشروع؟
- كل مبادرة تُكتب Issue أو Discussion باسمها وهدفها ورابطها ومهامها.
- حافظي على أن المستودع الأصلي @ahpa5246-lgtm هو المصدر الرئيسي، بينما يحتفظ الشركاء بحقوق إضافاتهم وفق الرخصة.
- لا تمنحي Credentials أو Admin أو مفاتيح Kaggle لشريك لا يحتاجها.
- عند استعمال نموذج طرف ثالث: اذكريه ورخصته وإصدار checkpoint، ولا تنشري أوزانًا أو بيانات صوت خاصة.
- قبل دمج كود طرف آخر: راجعي توافق الترخيص ونسب مؤلفيه، وتجنبي نقل مشروع آخر بالكامل بلا احترام MIT/GPL/Apache وشروطه.
- إذا اقترح شريك ميزات مغلقة أو غير قابلة للنشر: ادرسي مشروعًا منفصلًا أو سياسة مكونات واضحة؛ لا تعيدي ترخيص مساهمات الآخرين تلقائيًا.

## أين نبحث عن شركاء؟
- GitHub Projects المماثلة: شاركي **إصلاح bug لدى upstream** بدل الإعلان على قضاياهم.
- DEV Community وGitHub Discussions: طلب مراجعة تقنية محددة.
- مجتمع Blender Artists: Workflow صوت إلى فيلم Blender.
- itch.io/IndieDev: مشروع Game Jam يستخدم أصوات شخصية أصلية.
- الجامعات ونوادي البرمجة والروبوت: جلسة بناء صغيرة حول API/Audio tests.
- محاضرات مفتوحة المصدر والمجموعات التعليمية: شرح بنية API والاختبارات، لا وعود وظائف أو شهادات غير موجودة.

## برامج ومكافآت — دون استغلال أو وعد
- **GitHub Sponsors:** إن توفرت الأهلية وقدمتِ قيمة مستدامة، يمكن مراجعة إتاحة خيار التمويل. التبرع لا يمنح تلقائيًا حق فرض الميزة أو ملكية الكود.
- **Open Collective أو جهة داعمة:** تحققي من الإتاحة القانونية والضريبية والبلدان المدعومة قبل أي تعهد؛ لا تفترضي دعم العراق أو تفتحي رابط تمويل غير مفعل.
- **Hacktoberfest أو فعاليات المساهمة:** لا تُضيفي الوسم أو تدّعي المشاركة الرسمية إلا بعد فهم قواعد الموسم الحالي، وتجنبي PRs الوهمية لتجميع المكافآت.
- **Hackathons:** انضمي فقط إذا كانت حقوق IP واضحة وتتناسب مع ترخيص Mina؛ اقرأئي Terms.
- **Bounties:** لا تعِدي بمبالغ أو جوائز دون مصدر تمويل موثوق وشروط مكتوبة ومراجعة قانونية عند الحاجة. لا مكافآت مقابل Stars.

## كيف نعرف أن الشراكة ناجحة؟
- دمج PR مفيدة واحدة مع CI.
- توثيق مشروع/مقطع مستقل يعتمد Mina.
- اكتشاف وإصلاح مشكلة صوت أو تثبيت لا نعرفها.
- توصية علنية طوعية من مستخدم نجح بالفعل.
- محتوى تقني أصيل يذكر مؤسسة المشروع والمساهمين والمكتبات upstream بصورة عادلة.

## أول ثلاثة مشاريع تعاون مقترحة
- **Three Voices Mini-Scene:** ثلاثة شخصيات اصطناعية أصلية، 30 ثانية WAV/SRT وحوار متعدد المتحدثين، مع ملفات script وlicense.
- **Arabic Chatterbox QA:** عشر جمل عربية عامة؛ قياس أخطاء ASR وتقييم حروف حساسة، من دون تسجيل صوت شخص آخر.
- **First Install Challenge:** متطوعون من أنظمة مختلفة يوثقون مشاكل التثبيت مع سجلات منقحة ويقدمون PR README.

## مخاطر الشراكات
طلب وصول كامل للمستودع، نسخ كود بترخيص غير متوافق، نسب مساهمات غير صحيحة، استضافة مفتوحة بلا أمن، المشاركة بتوكنات/أصوات حساسة، وادعاء شراكات رسمية مع شركات لم تؤكد ذلك. أي عرض بهذه العلامات يُوقف لحين المراجعة.
