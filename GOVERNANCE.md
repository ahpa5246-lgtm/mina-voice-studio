# Governance — Mina Voice Studio

## Founder and scope
Mina Voice Studio was initiated by **Mina Hussein Salman**, who leads the canonical repository at @ahpa5246-lgtm. It is an open-source workstation for locally controlled cartoon voice production. Its original vision and founding history should remain visible even as the community grows.

## Decision-making
- Anyone can open a reproducible bug report, suggest a feature, or submit a Pull Request.
- Scope large ideas in a public Issue or Discussion first. Small safe fixes need an Issue or a clear PR explanation.
- The founder is currently the lead maintainer and has final approval for merging into the canonical repository and publishing releases. Reasons for accepting or declining contributions should be stated respectfully and technically.
- Co-maintainers may be added later with documented permissions and responsibilities. A maintainer role does not transfer contributors' copyrights.
- Review for soundness: tests, error paths, compatibility, upstream licensing, speaker consent, secrets safety and truthful model-performance claims.
- Give authors credit in commit history, PR acknowledgements and release notes. Contributions are never conditioned on stars or promotional posts.

## Conflict resolution and safety
Use the [Code of Conduct](CODE_OF_CONDUCT.md). Discuss code changes publicly and report vulnerabilities privately under [SECURITY.md](SECURITY.md). Avoid identity attacks or deletion of third-party attribution.
The original account controls the canonical repository. Forks are permitted under the actual MIT terms; CODEOWNERS can request review only when the corresponding GitHub rules are enabled. This is not a legal exclusivity claim over the idea itself.

## Release process
Each release must state what changed, which tests ran, what was not validated on real neural models, and which contributors participated. Never present synthetic test fixtures as measured neural speech.
